# 测量层手册：留出集、哈希锁与进步读数（measurement_guide）

> 升级自 test_tutor@a25df33 的 `references/measurement_guide.md`。v1.5 的改动只有三处：
> ①`held_out.md` 每题附「关键步骤清单」（供零 LLM 判推理链）；②明确「零 LLM」只覆盖客观题路径；
> ③推理链旗标单列记录，**不进入** McNemar 读数。其余机制（物理隔离、哈希、盲评同批、降级声明）原样保留。

## 1. 留出集是什么、为什么碰不得

- `held_out.md` 是建库时从真题里切出的一小组题（3–5 题），独立成文件，**日常绝不打开**。全备考期只打开两次：第 0 周基线测一次、考前一周重测一次。
- 为什么必须物理隔离，而不是在日志里打个「属于留出集」的标记：AI 是按路径读文件的，标记字段依赖模型每次都记得过滤，而模型会在长会话、上下文压缩、多轮跳转中漏掉——只要漏一次，「见过这道题」就混进前后测差值，整个验证永久失效。独立文件是唯一不依赖模型自觉性的做法。
- 日常练习出题、变式题生成、Obsidian 笔记生成，**永远不读** `held_out.md`。出题材料只来自日常池（真题其余部分、讲义例题、AI 生成）。

## 2. held_out.md 的结构（v1.5）

每题一个区块，答案与关键步骤清单**建库时一次写定**：

```markdown
## H1 <题干 / 题号>
- 类型: 客观
- 答案: B
- 关键步骤清单:
  1. 由题干条件 X 得到 Y
  2. 用规则 R 排除 A/C
  3. 得出 B
```

- 「关键步骤清单」的来源：M-A 档从官方解析**机械提取**；M-B 档只需客观题，清单同样从解析提取；M-C 档无留出集，不适用。
- 清单是**测量时唯一的判链依据**：重测时你对照清单自判「是否成立」，不再让模型现场生成步骤——现场生成等于把漂移请回测量层。
- 清单与题目同文件，因此**自动被哈希覆盖**。改清单 = 改留出集，必须走 `--record` 留痕。
- M-C 档的 `held_out.md` 是三行声明文件（「本考试无留出集」+ 原因 + 放弃了什么），不留空文件、也不缺文件。

## 3. 哈希校验流程（SHA-256）

留出集的价值 100% 依赖「重测的题就是基线测的那些题」。用哈希把这件事变成可机检的：

| 时机 | 动作 | 命令 |
|---|---|---|
| 建库切分后 | 记录哈希 | `python <skill>/scripts/verify_heldout.py --record <工作区>/held_out.md` |
| 每次重测前 | 校验哈希 | `python <skill>/scripts/verify_heldout.py --verify <工作区>/held_out.md` |
| 校验 FAIL | 停下，走 §3.1 | — |

- 哈希文件 `held_out.md.sha256` 与 `held_out.md` 同目录，格式 sha256sum 兼容（`<小写hex>␣␣held_out.md`，两空格）。
- Python 不可用时的等价命令：PowerShell `Get-FileHash -Algorithm SHA256 held_out.md` 后手工比对。
- `--verify` 失败 = 非零退出。FAIL 不是坏消息，是哨兵在响——按 §3.1 处理，不要重跑了事。

### 3.1 校验 FAIL 后的分支

1. **有意修改**（你确实换过题、改过步骤清单）：重新 `--record` 记录新哈希，并在 `INDEX.md` 注明修改日期与原因——留痕防静默污染。
2. **无意修改**（你没动过它）：从备份恢复（工作区建议 git 版本化，或建库时另存 `held_out.md.bak`）；恢复后重跑 `--verify` 必须通过，再进重测。

**信任边界**：哈希文件与 `held_out.md` 同目录、同写权限，本机制**不防「有意同时改写两者」的篡改**——那需要独立存储或签名。它防的是无意改动与自我欺骗。所以有意修改必须走「重录 + INDEX 注明」，而不是悄悄重录。

## 4. 基线与重测（客观题路径，零 LLM）

1. 第 0 周：打开 `held_out.md`，限时作答。作答前先标信心、写一行依据（推理链），做完后**对照文件里的答案自判对错**、**对照关键步骤清单自判链态**。
2. 每题结果进 `answer_log.csv`，「是否留出集」列写「是」；基线总分回填 `learner_profile.json` 的 `baseline_score`。
3. 考前一周：**先跑哈希校验**，通过后再限时作答、自判记分。
4. 两次记分按题配对，读数见 §6。

这条路径上没有任何模型参与判分：信心是你标的、对错是你对照答案判的、链态是你对照清单判的。模型换一百次，前后测分数都不动。

## 5. 主观题进测量层：盲评同批法（有模型，但同源）

主观题占大头的考试不能回避。解法不是让模型稳定，而是**让两次测量共用同一个「当下」**：

1. 基线作答与考后作答，**打乱顺序、匿名编号**（甲/乙/丙……）。
2. 放进**同一个对话、同一个模型实例、一次性批改完**（含 §4.1 的链判定表 + 采分点命中表）。
3. 批完再解盲，把结果回填到各自的时间点。

- 原理：两次测量共享同一个评分器状态。不依赖「模型不变」，而依赖「两次在同一时刻」。
- **单批上限 10–15 题**；超过后长上下文会让后半段质量下降。题多就拆成多个混编批，每批内部仍走 1–3 步；批与批之间不互相参考。
- 前提是有步骤清单（M-A）；M-B 档无细则，主观题不进测量层（`material_tiers.md`）。
- 这条路径**不是零 LLM**。它把漂移从「两次测量之间的漂移」压成「一次批改内部的偏差」，代价是仍需人工解盲。把它和 §4 的零 LLM 路径分开记账，不要向自己声称「我的测量完全没有模型」。

## 6. 读数：McNemar 四格计数

留出集 20 题是 20 个观测单位，不是 1 个。按题配对计数：

|        | 考后对 | 考后错 |
|---|---|---|
| 基线对 | a | c |
| 基线错 | b | d |

- 只看不一致的两格：`b`（基线错 → 考后对）与 `c`（基线对 → 考后错）。
- 原假设下 `b/(b+c)` 服从二项分布 `(b+c, 0.5)`，用精确二项检验。例：b=15、c=4 → p ≈ 0.009。
- 代价要说清：它只回答「有没有变化」，不回答「变化有多大」。技能只要求把四格数出来，p 值用任意二项计算器手算，不引入统计依赖。
- **推理链旗标不进这张表**：McNemar 数的是「这次答案对不对」，链态是另一个问题。两者分开记录，报表里也不合并——把链态折进读数会同时污染两个结论。

## 7. 跨领域多基线设计（可选，不默认启用）

- 选 A、B、C 三个相对独立的领域，A 从第 0 周开始强化、B 从第 3 周、C 从第 6 周；每周对三个领域各测 5–8 题。
- 判读：某领域只在自己干预启动后跃升、启动前平稳 → 干预有效的证据。备考中不可能「撤除学习再重测」，这是单被试研究的标准替代。
- 适用条件：领域间不能有强迁移。数据照常进 `answer_log.csv`（`是否留出集=否`），按模块逐周聚合观察。
- 效应量口径：单被试用 Tau-U（干预期数据点超过基线期数据点的比例），不用 Cohen's d。启用本项的那一周不排其它测量动作。

## 8. 降级声明：最终验证是真实考试本身

- 对个人备考，**最终验证是真实考试**。
- 留出集回答的是「我现在该不该上考场」「哪块还差多少」——是决策辅助，**不是统计证明**。
- 不要向自己声称「我的系统被验证有效」。可以说的是：「我在留出集上的正确率从 X 升到 Y，且集中在第 3、5 章。」

## 9. 材料档对测量层的影响

| 材料档 | 测量层状态 |
|---|---|
| M-A | 全功能：客观题零 LLM 自批 + 主观题盲评同批 |
| M-B | 留出集仅客观题；主观题不进测量层 |
| M-C | 无留出集验证（`held_out.md` 为显式声明文件） |

## 10. 附录：执行口径澄清

- **跑哈希校验算不算「打开」held_out.md？** 不算。校验只对文件字节做摘要，题目内容不进对话上下文。
- **基线测完想看解析？** 可以——该次测量已完成、题目已消耗；基线与重测之间的学习本就是设计的一部分，但看解析要发生在记分之后。
- **留出集的题能进 Anki 吗？** 不能。`export_anki.py` 导出与回填都跳过「是否留出集=是」的行；间隔重复会在重测前反复暴露它们。
- **留出集能进 Obsidian 吗？** 绝不。vault 里任何位置都不允许出现留出集题目、答案、步骤清单；`obsidian_sync.py` 遇到 `held_out*` 路径直接拒绝。哈希锁只依赖 `held_out.md` 本身。
- **可以打印出来做吗？** 可以——纸质作答不经过 AI 上下文，自批判分照常；打印件用完处理，不要回流成练习材料。

## 11. 与其他文件的衔接

- `SKILL.md`：测量动作只出现在周清单的两个时点（第 0 周与考前一周），无任何自动触发。
- `grading_guide.md`：客观题自批判分、两步链判定表、盲评同批。
- `material_tiers.md`：档位决定测量层可用品类。
- `scripts/verify_heldout.py`：§3 的执行脚本（`--record` / `--verify`）。
- `scripts/obsidian_sync.py`：§10 的留出集禁令在该脚本中被硬编码（路径命中 `held_out*` 即拒绝）。
