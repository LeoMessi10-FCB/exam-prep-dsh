# 讲授流水线：Concrete First / Chunking / Generation（teaching_pipeline）

> 定位：日常循环「出题 → 先标信心 → 作答 → 批改 → 错因记录」之外的**前置补给**。某个模块还没建立可用的概念结构时，先讲一次再出题，比继续在错题里打转有效。
> 本文是讲授动作的真源：SKILL.md 的「先讲一下」路由、以及与 CPKG 中 C（概念性错误）处置的衔接，都引用本文；本文不重复 SKILL.md 的会话编排。

## 1. 触发条件（硬规则，二选一即可）

满足任一条即进入讲授流水线：

1. **数据触发**：`syllabus_table.csv` 中该模块「我的掌握度」为 `0.00`；或该模块在 `answer_log.csv` 中**尚无任何作答行**（新模块、从未练过）。
2. **口头触发**：用户显式说「先讲一下 / 讲一下 / 先讲讲这个」（含同义变体，如「这块没懂，先讲讲」「你先给我讲讲」）。

- 每模块**默认只讲一次**；讲完即视为「已讲授」，后续不再自动重复。
- 用户可**再要求**（「再讲一遍」「还是没懂」）：重复触发合法，但每次都要**完整重走本流水线**，不许只丢一段定义充当复习。
- 触发判断由会话内 AI 完成，不需要用户记规则；AI 判断命中数据触发时，先说明「这个模块还没有可用的概念结构，先讲一版」，再开始讲。
- 讲授不等于跳过练习：讲完紧接「出题」（见第 5 节），不许以「讲完了」作为一轮的终点。

## 2. 三件套的可检验定义

三件套不是风格偏好，每一条都能被逐句核对。缺一条即视为未完成讲授，重做。

### 2.1 Concrete First（具体先行）

- **输出的第一句必须是一个具体场景/具体例子**：有人、有数、有事发生。
- **禁止以定义、术语、公式开场**。首句出现「XX 是指……」「XX 的定义是……」「根据公式……」即不合格。
- 判据：把第一句单独摘出来，非本专业的人也能听懂「发生了什么」，且能追问「然后呢」。

### 2.2 Chunking（分块）

- 关键块 **≤3 个**（超过 3 个说明这一讲该拆成两讲）。
- 每块 **2–3 句**，只承载一个判断。
- 每块**必须含一句「边界或反例」**：这条什么时候不适用、哪种情形会被它误判。缺这句的块视为不合格——只讲适用范围、不讲失效边界，是把概念讲成口诀。

### 2.3 Generation（先产出，后对照）

- 讲完三块，**先让用户用 ≤3 句自己的话总结**，然后停住。
- **用户说完之后**，才给标准表述，并给三列差异表：`你写的 | 标准表述 | 差异类型（漏项/错连/术语错）`。
- **用户没总结前不得先给标准表述**——先给答案再让复述，得到的是模仿，不是检验。
- 差异类型只用三档，且必须落到具体字句：
  - **漏项**：标准表述里的关键要素在你的总结里没有出现；
  - **错连**：要素都在，但因果/条件关系接错（把「充分」说成「必要」这类）；
  - **术语错**：意思对但用了错的名字，或用了 syllabus 之外的自造词。
- 不对差异表做措辞评价（见第 4 节）。

## 3. 输出骨架（可复制，顺序固定）

```markdown
【场景】<一个具体场景：有人、有数、有事发生。第一句就是它，不许先给定义>

【块 1】<2–3 句，一个判断>
        边界：<这条什么时候不适用 / 反例>

【块 2】<2–3 句，一个判断>
        边界：<……>

【块 3】<2–3 句，一个判断>
        边界：<……>

【你先说说】用不超过 3 句话，把这个模块讲给一个没学过的人听。说完我再给标准表述。

——（用户回答后）——

【标准表述】<一段，覆盖三块的关键要素>

| 你写的 | 标准表述 | 差异类型（漏项/错连/术语错） |
|---|---|---|
| <原句摘录> | <对应句> | <漏项 / 错连 / 术语错> |

【自测】<1 道一句话能答完的题，考边界，不考背诵>
```

骨架的顺序不可调换：场景 → 三块 → 「你先说说」提示 →（用户回答后）标准表述 + 差异表 → 一句自测题。

## 4. 禁忌

- **不给完整解题过程**：讲授给的是概念结构与边界，解题步骤留给「出题 → 批改」环节；讲完就把题做完，等于用讲授替代练习。
- **不评价用户措辞与流畅度**：差异表只判「漏项/错连/术语错」，写「表达不够专业」「逻辑不够清楚」一类评语即越界。
- **不引入 syllabus 之外的模块**：超纲内容会把掌握度与错因统计带偏；确实必要的新概念，先回 `syllabus_table.csv` 补行，再讲。
- **单次讲授 ≤15 分钟**：到点即止，宁可拆成两次，也不拖成一节网课。

## 5. 与日常循环的衔接

- 讲完**立即接「出题」步骤**，同一会话内完成，不隔天、不隔轮。
- 出的题**必须落在刚讲的模块上**（`answer_log.csv` 的「模块」列取同一个值），且**至少 1 题考应用层**——只考定义的题无法检验边界是否真的建立了。
- 题目仍走标准流程：先标信心三档（稳/不确定/蒙），再作答，再批改、记错因。讲授不改变作答与判分的任何口径；是否「疑似蒙对」由日常循环的伪装漏洞检测口径判定（见 `error_taxonomy.md`），讲授环节不另设判据。
- 首轮题的正确率就是这一讲的验收信号：全对且信心为「稳」→ 该模块转入常规节奏；仍错 → 按第 6 节走 CPKG 处置，而不是加讲第四块。

## 6. 与 CPKG 的关系

- 错因 **C（概念性错误）**的处置是「返回讲解材料，重新出题（同类）」——这类模块**优先走讲授**，而不是继续刷题。同一概念连续错却重复出题，只是在收集同一种失败。
- 对照口径：C 偏「讲」，P（程序性）偏「分步模板 + 同类题 3 道」，K（粗心）偏「重点复出 + 写步骤」，G（覆盖缺口）偏「排进计划」。讲授流水线只负责 C 与 G 的补给段，不接管 P/K 的处置。
- 同一知识点累计 ≥3 次 K 错误会被标为「疑似概念漏洞」并强制出题；此时若用户仍反复错，按 C 处理、走讲授，不要继续用「再细心点」敷衍。

## 7. 预算规则

- 讲授单次 **≤15 分钟**，计入当周用户侧净投入。
- 讲授**触发周**的「三个领域小测（可选 30 分钟）」**顺延到下周**。周预算口径（与 SKILL.md 周清单逐项一致）：
  基础周 = 1（追加日志）+ 10（掌握度 + INDEX）+ 10（变式题）+ 3（Anki 回填）+ 5（推理链写作）= **29 分钟**；
  开启可选小测 = 29 + 30 = **59 分钟**（已贴上限）；讲授触发周顺延小测 = 29 + 15 = **44 分钟**。三者均 ≤60。
- 讲授不额外增加「复习讲授内容」的固定动作：检验靠随后的出题与周报里的掌握度变化，不靠复述打卡。
- 一周内讲授模块多于 2 个时，说明是建库排序出了问题（权重档给错或模块切太细），回 `syllabus_table.csv` 修表，而不是把预算撑大。

## 8. 与 Obsidian 的映射（仅在绑定时生效）

未绑定 Obsidian 时本节不适用，讲授产物只存在于会话与 `answer_log.csv`。

绑定后，**一次讲授 = 一条概念笔记** `concepts/<exam>/<module>.md`，节与骨架一一对应：

| 骨架元素 | 笔记小节 |
|---|---|
| 场景 | `## 场景` |
| 块 1 / 块 2 / 块 3 | `## 块 1` / `## 块 2` / `## 块 3` |
| 标准表述（含差异表结论） | `## 标准表述` |
| 自测题 | `## 自测` |

- 笔记的 frontmatter（考试、模块、日期等）由 `obsidian_sync.py` 写入；本文只描述映射，不描述脚本参数与调用细节。
- 差异表本身不落笔记（它是一次性的对照产物）；只把「标准表述」的定稿写进 `## 标准表述`。
- 重复讲授同一模块时**覆写同一条笔记**，不新建 `-2` 文件；版本差异靠 Obsidian 自身的文件历史，不在工作区留副本。

## 9. 与其他文件的衔接

- **SKILL.md**：「先讲一下」路由与日常循环第 1 步（出题）之前的讲授入口引用本文；本文件不重复会话编排与分诊逻辑。
- **syllabus_table.csv / answer_log.csv**：触发条件 ① 直接读这两份文件（掌握度列、模块列的作答行有无）；讲授后出的题必须回到同一「模块」取值。
- **error_taxonomy.md**：C/G 的处置口径以该文件为准，本文只说明「走讲授」这一分支；信心三档与疑似蒙对的判据不在本文定义。
- **item_writing_guide.md**：讲授后那组题（含至少 1 题应用层）按该文件的出题规范写，干扰项须反映常见误解。
- **weekly_report.py**：讲授不新增统计口径；其效果只体现在后续周报的掌握度变化与错因分布上。
- **obsidian_sync.py**：第 8 节的笔记映射由该脚本落盘，frontmatter 字段以脚本契约为准。
