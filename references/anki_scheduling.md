# Anki 调度回填与掌握度折扣（anki_scheduling）

> 定位：把 Anki 的「到期未过 / 重新学习」信号**回填**进 `answer_log.csv`，让掌握度能看见「记住了但没复习」这一层折扣。回填是可选动作，不绑定 Anki 也能正常备考。
> 本文是回填列、回填命令、折扣公式的唯一真源；`export_anki.py --import-due` 与 `mastery_calc.py` 的口径冲突时以本文为准。

## 1. 边界声明（先声明，再谈功能）

- 本技能只做 **CSV 桥**：Anki 的到期清单由**用户手动导出或回贴成 CSV**，技能只读这份 CSV。
- **不读 Anki 运行时数据库**（`.anki2` / collection 文件），**不做 Anki 插件式集成**，不调用 AnkiConnect，不假设 Anki 已安装、已运行或版本为何。
- 因此「到期」的判定发生在 Anki 侧，「是否值得折价」的判定发生在技能侧：技能只消费清单，不解释清单怎么来的。
- 蓝本口径如此，不是本轮未实现——换成直连数据库会引入一套无法自检的运行时依赖，与本技能「轻量文件 + prompt」的形态冲突。

## 2. 列契约

`answer_log.csv` 在核心列之后追加一列 `anki状态`（中文列名，与既有列风格一致）：

- 取值 ∈ {`未过`, `重学`}；`未过` = 到期未通过，`重学` = 被 Anki 重新学习。
- **空 = 尚未回填**，是合法状态，不是缺数据。`validate_log.py` 不对空值告警（该列可选）。
- 全表该列全空时，掌握度输出与没有这一列**逐位一致**（见第 5 节单调性与兼容性）。
- 该列由回填命令写入，**用户手填合法但不推荐**：手填无法被「只填空」约束保护，也进不了回填统计。

## 3. 回填契约

```bash
python <skill>/scripts/export_anki.py --import-due <清单.csv> --workspace ~/exam-prep/exams/<id>/ [--dry-run]
```

- `<清单.csv>` 至少含 `date,模块` 两列，**可以多列**（题目、题型等额外列忽略不用）。
- 匹配键 = **(date, 模块)**：日期按 `YYYY-MM-DD` 字面比较，模块按字符串全等比较，不做模糊匹配、不做日期归一化。
- 写入规则：
  - **只填空白单元格，永不覆盖已有值**。已有 `未过`/`重学` 的行原样保留，即使清单里写了别的值。
  - 同一键（date, 模块）在日志里命中**多行**时，取**日志里最后一行**写入，并在 stdout 报「多义」条数（便于判断日志是否该去重）。
  - 命中「是否留出集 = 是」的行**一律跳过**：留出集不进 Anki，也不接受调度信号，回填不得给它们打标。
  - 清单里在日志中**找不到对应的 (date, 模块)** 的条目：计入统计并在输出中列出（不要静默丢弃——找不到往往意味着清单日期或模块名与日志不一致）。
- `--dry-run`：只打印将写入的行与三类统计（命中 / 多义 / 未匹配），**不落盘**。首次回填建议先跑 dry-run 对一眼。

## 4. 与 append-only 的窄例外

`answer_log.csv` 是追加式日志，「绝不改历史行」是硬约束。**本文件描述的是该约束的唯一窄例外**，边界四条，缺一即违规：

1. **只能改 `anki状态` 这一列**，其他任何列（对错、信心、错因、日期、模块……）一个单元格都不许动。
2. **只能把空填成非空**，不得把 `未过` 改成 `重学`、不得清空、不得改写成第三种值。
3. **不得改动任何其他单元格**，包括格式、列顺序、行顺序；新增列只在表尾追加，历史行在该列补空（纯结构迁移）。
4. **每次回填在 `INDEX.md` 记一行**：日期 + 回填条数（例：`2026-11-02　anki 回填 12 条`），让「什么时候动过日志」可追溯。

违反任一条即视为**污染历史**，按「改历史」处理：从备份回滚日志、在 INDEX.md 记一条回滚说明（日期 + 回滚原因），然后重跑回填。回填失败宁可重跑，不要「手工补一补」——手工补正是污染历史的典型入口。

## 5. 掌握度折扣公式（完整可复算）

```
frac_due = 该模块 anki状态 非空的行数 / 该模块总行数
mastery  = clamp( base × (1 − w × frac_due), 0, 1 )
```

- `base` = 原四项公式的结果：`0.4 × 正确率 + 0.3 × (1 − 高置信度错误惩罚) + 0.2 × 趋势 + 0.1 × 充分度`（口径与 `mastery_calc.py` 现版完全一致，本文不改四项中的任何一项）。
- `w` = 折扣权重，**默认 0.15**，可用 `--anki-weight` 调整；调整只影响折扣项，不影响 `base`。
- `clamp(x, 0, 1)` 截断到 `[0,1]`；输出仍保留两位小数（与原契约一致）。
- `frac_due` 的分母是**该模块总行数**；分子只数该模块中 `anki状态` 非空的行。留出集行按第 3 节被回填跳过，因此通常保持为空——它们被排除在 Anki 之外，不代表已复习。

**为什么用乘性折扣，而不是往四项里加第五项：**

1. **四项语义不被破坏**：加第五项会改变权重分配（0.4/0.3/0.2/0.1 的语义变成「五分之一块」），原公式不再可解释；乘性折扣单独可解释为「调度违和」——「你练得不错，但有一批题在 Anki 里没通过，实际留存打折」。
2. **单调且恒 ≤ base**：`frac_due ≥ 0`、`w ≥ 0` 时因子 `1 − w·frac_due ≤ 1`，掌握度只会因调度违和而下降，不会出现「Anki 没通过反而抬高掌握度」的荒谬结果；对 `frac_due` 严格单调递减。
3. **列不存在时输出与蓝本逐位一致**：没有该列或全空时 `frac_due = 0`，因子为 1，折扣不进入计算——兼容性不靠条件分支保证，靠公式本身保证。

`w` 的上界由 `frac_due ≤ 1` 给出：`w > 1` 会让因子为负、被 clamp 成 0，等于「只要有一行没通过就归零」，不建议；`w` 取 0.15 时最大折价 15%。

## 6. 两个算例（合成值，逐步可复算）

**例 1：有调度信号**

- 该模块 `base = 0.72`，共 10 行，其中 3 行 `anki状态` 标 `未过`。
- `frac_due = 3 / 10 = 0.30`
- 因子 = `1 − 0.15 × 0.30 = 1 − 0.045 = 0.955`
- `mastery = 0.72 × 0.955 = 0.6876` → 输出 **`0.69`**

**例 2：无调度信号（或未绑定 Anki）**

- 该模块 `base = 0.55`，共 10 行，`anki状态` 非空 0 行。
- `frac_due = 0 / 10 = 0`
- 因子 = `1 − 0.15 × 0 = 1`
- `mastery = 0.55 × 1 = 0.55` → 输出 **`0.55`**（与不装本机制时逐位一致）

## 7. 读数口径

- 折扣**只影响「建议值」**：`mastery_calc.py` 输出的是建议掌握度，`syllabus_table.csv` 的「我的掌握度」是用户可手改的列；**手改值不被脚本覆盖**（D-12 语义保持）。折扣是提示，不是裁决。
- 周报必须**单列「Anki 调度回填」计数**：本周回填了多少条、涉及几个模块。这样看到掌握度下降时，能立刻判断「是练得差了」还是「只是多了 12 条没过的信号」——没有这个计数，折扣就是个黑箱。
- 折扣幅度可解释：`w=0.15` 时，`frac_due=0.2` 折 3%，`frac_due=0.5` 折 7.5%；若某模块折价超过 10%，正确处理是回去清 Anki 到期清单，而不是调小 `w`。

## 8. 与 Obsidian 的映射（仅绑定时）

- 绑定时，错题笔记的 frontmatter 可同步写 `anki_due: true`（对应 `未过`）/ `anki_relearn: true`（对应 `重学`），供 Obsidian 侧 Dataview 做看板与筛选。
- **仅供展示，绝不回流**：这些字段是工作区 → 笔记的单向投影；不得从笔记读回工作区、不得据笔记内容改写 `answer_log.csv` 或掌握度。单向性是本映射成立的前提。

- **SKILL.md**：Anki 导出是可选动作，入口与时机（建库后、周操作清单）由 SKILL.md 编排；本文只管回填与折扣的契约。

- **mastery_calc.py**：消费 `anki状态` 列实现第 5 节公式；`--anki-weight` 为其参数，默认 0.15。
